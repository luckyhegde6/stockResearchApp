# v1.19 Changes — Screener Export-Free Public Pagination

## Reason
Screener's Export control can redirect a public user to the login screen. The market-screen collector therefore no longer attempts Export in any form.

## Acquisition policy
- `exportAttempted=false` by design.
- No click on Export.
- No direct Export href request.
- No premium/login workflow.
- Public HTML result pages are collected with `?page=N`.

## Pagination
1. Open page 1.
2. Read `results found` and `Showing page X of Y`.
3. Fetch pages 2..Y.
4. Parse the largest populated result table on each page.
5. Preserve page-level raw rows and headers.
6. Merge and deduplicate deterministically.
7. Compare final row count with the page-1 declared total.

## Output
Each screen folder contains:
- `results.json`
- `metadata.json`
- `page-01.json`
- `screen-page-01.png`
- `pages/page-01.json ... page-N.json`

The market-screen index records the acquisition policy and row-count checks.

## Data quality
The collector records:
- declared result count
- total pages
- rows captured per page
- deduplicated rows
- duplicate row count
- row-count delta
- column headers
- public query text when available

No values are inferred by an LLM.
