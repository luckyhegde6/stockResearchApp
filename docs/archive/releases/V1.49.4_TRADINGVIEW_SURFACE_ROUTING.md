# v1.49.4 — TradingView Metrics Surface Routing

## Problem fixed

v1.49.3 successfully clicked the current TradingView **Metrics** launcher, but the transient menu item click was still not reliable. Logs showed `launcherClicked=true` while `surfaceClicked=false` for Forecast/Documents/Seasonals and Community.

The screenshots confirm the current layout contains a compact right-side Metrics menu with exact labels: Financials, Documents, Technicals, Seasonals, News, Forecast, Community, Options and ETFs. The adapter previously over-constrained the menu container and could reject the real DOM despite the visible menu.

## New strategy

1. Open the dynamic `https://in.tradingview.com/chart/?symbol=NSE:<SYMBOL>` chart.
2. Click the stock-card **Metrics** launcher.
3. Find visible exact surface text in the right-side transient menu.
4. Click the exact visible label by geometry.
5. Wait for surface-specific confirmation.
6. If SPA navigation is not confirmed, navigate with Playwright to the corresponding public symbol page.
7. Confirm the page by route and/or strong surface-specific content.
8. Capture the screenshot only after the surface is actually confirmed.

## Public symbol routes

- Forecast: `/symbols/NSE-<SYMBOL>/forecast-price-target/`
- News: `/symbols/NSE-<SYMBOL>/news/`
- Documents: `/symbols/NSE-<SYMBOL>/documents/`
- Seasonals: `/symbols/NSE-<SYMBOL>/seasonals/`
- Community: `/symbols/NSE-<SYMBOL>/community/`

## Quality rule

A UI surface is `ok` only when surface confirmation succeeds and the screenshot exists. A screenshot of the chart/menu alone remains `partial`.
