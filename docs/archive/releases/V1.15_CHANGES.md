# v1.15 — Normalization & Evidence Contract

## Purpose
Lock the acquisition layer and create a deterministic, source-aware contract between acquisition/normalization and the final LLM.

## New outputs
- `source-health.json`
- `evidence-quality.json`
- `evidence-contract.json`
- `evidence-bundle.json`
- `raw/tradingview/technical-normalized.json`

## Evidence contract sections
- `FACTS` — source-derived factual values.
- `CALCULATED_METRICS` — deterministic metrics calculated from canonical data.
- `SOURCE_EVIDENCE` — validated presence/provenance references for source content.
- `DATA_QUALITY` — deterministic quality measurements.
- `CONFLICTS` — deterministic cross-source inconsistencies when detected.
- `WARNINGS` — operational/source limitations.

## Key semantics
- `source_extraction` is used for observed source values.
- `deterministic_calculation` is used for indicators such as EMA50, EMA200 and RSI14.
- TradingView EMA fields can be considered verified when the canonical deterministic technical dataset provides the values; TradingView itself remains visual/audit evidence.
- BSE annual-report absence is handled as delegated evidence because NSE is the primary annual-report evidence source.
- Fallback failures that are successfully recovered are informational rather than actionable warnings.
- Warning counts are deduplicated before aggregation.
- `llmUsed=false` for acquisition/normalization/validation.

## Final LLM boundary
The final prompt consumes `evidence-contract.json`, `source-health.json`, and `evidence-quality.json` before the detailed Markdown evidence. The LLM is not asked to discover basic facts from 30+ raw artifacts.
