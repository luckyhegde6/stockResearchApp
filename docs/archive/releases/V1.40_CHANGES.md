# v1.40 Changes

Chartink scanners that remain empty after a bounded Run Scan are now treated as a valid `no_results` state.

- No CSV click is attempted after confirmed zero results.
- No Copy click is attempted after confirmed zero results.
- Disabled controls cannot cause long selector timeouts for this state.
- `resultStatus=no_results` and `noResults=true` are persisted.
- No data gap/warning is generated solely for a legitimate zero-result scanner.
- The strategy loop immediately proceeds to the next configured scan.
- Initial `/screener/process` waiting is shortened and skipped for confirmed no-results pages.
