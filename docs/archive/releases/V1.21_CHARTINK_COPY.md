# v1.21 — Chartink Copy → Table → OK acquisition

## Why
Chartink scanner pages can expose result data in the public table, while the internal `/screener/process` response can be empty or shaped differently from the rendered table. The collector therefore treats the visible table and Chartink's public Copy workflow as first-class deterministic acquisition paths.

## Copy workflow
For every configured strategy the adapter opens a fresh Playwright page and:

1. Finds the public `Copy` control.
2. Clicks `Copy`.
3. Selects `Table` in the copy dialog when present.
4. Clicks `OK`.
5. Reads clipboard text through the browser context.
6. Parses the copied table deterministically.
7. Saves the copied table to `raw/chartink/strategies/<slug>.copy.txt`.
8. Also attempts the visible `CSV` download button, when available.

No login, premium export, or LLM is used.

## Fallback order

`Copy → Table → OK` → visible DOM result table → `/screener/process` network response → browser POST fallback.

The Copy/CSV workflow is not required to succeed for every strategy; the result source is recorded explicitly.

## Page lifecycle
Each strategy uses a fresh page inside a shared browser context. This prevents one closed/poisoned page from causing all subsequent strategies to fail.

## Debugging
Each strategy logs:

- copy control detection
- copy dialog / OK workflow
- clipboard character count
- visible table row count
- process response presence
- CSV capture
- normalized stock count

The Chartink strategy search also uses its own fresh page.
